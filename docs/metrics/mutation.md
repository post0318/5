# 심은 오류(mutation) 시험 — 검증기 검출률 — 2026-09-26

`scripts/metrics/mutation.mjs`. 검증기(`scripts/verify-financials.mjs`)가 **실제로 있었던 오류 유형**을 잡는지 상시로 잰다.
골든셋(`golden.mjs`)이 "값이 바뀌었나"를 본다면, 이 시험은 "틀린 값이 들어왔을 때 검증기가 알아채나"를 본다.

---

## 1. 목적 — "검출률" 관문

- 지표(매출·매출원가·…)를 **닫으려면** 그 지표에 관련된 심은 오류가 **모두 검출**돼야 한다.
- 예외는 이 문서 §5 "알려진 공백"에 **사유와 함께 적힌** 항목뿐이다. 목록에 없는 미검출은 "새 공백"이고, 새 공백이 하나라도 있으면
  그 지표는 닫지 않는다(검증기를 고치거나, 공백으로 인정할지 오너 결정 후 §5 에 적는다).
- "검출" = 기준선(심기 전)에 없던 **FAIL 검사 · ③ 오류(외부 대조) · 조회 실패(hardErrors)·종목 오류**가 새로 생김.
  ①·②·통과·공통모드·검증불가로 분류되는 것은 **검출이 아니다**.
- 이미 기준선에서 실패 중인 같은 검사의 메모만 바뀐 경우는 "기존 실패에 가려짐"으로 따로 보이고 검출로 세지 않는다.

## 2. 방식

1. 종목마다 **기준선**(심기 없음) 1회 → **대조군**(심기 없음, 캐시로 다시) 1회 → 목록의 심기마다 1회. 검증기는
   `--metric=cogs`(기본 검사 + 매출원가 검사 전부)·`--concurrency=1`·종목 1개씩 돈다.
2. 심기는 **검증기 쪽 가로채기**다 — `node --import scripts/metrics/mutation.mjs` 가 검증기 프로세스의 `fetch` 를 감싸 앱 응답
   JSON 을 바꾼다. 앱 코드·앱 서버·운영 DB 는 건드리지 않는다. 앱에는 GET 만 허용(검증기 `--post` 경로 차단).
3. 심기 방식
   - `replace`: 앱 응답 전체(하이라이트·재무분석·개요·TTM·컨센서스·손익·대차대조표·총괄·verify-row)에서 숫자 `from` 과 **정확히 같은**
     값을 `to` 로 — 계산층 결함이 모든 화면에 같이 퍼진 상황을 흉내 낸다. `kinds` 로 한 화면만 바꿀 수도 있다(화면 간 불일치).
   - `fn`: 행 삽입 등 구조 변경(유형 D 매출원가 행).
   - `fx`: 검증기가 받는 Yahoo 일별 환율도 함께 바꾼다(환율 원천이 틀린 공통모드 재현).
   - 파생값(성장률·마진·PSR 등)은 따로 고치지 않는다 — 그래서 "어느 검사가 잡았나" 칸에 C·D층 재계산 검사가 같이 뜰 수 있다.
     **기대 층(expect)**이 발화했는지를 따로 본다: 기대 층이 없으면 상태가 "검출(기대 층 아님)".
4. **캐시**: 첫 실행(기준선)의 SEC·Yahoo·인포맥스·StockAnalysis·앱 응답을 저장하고 나머지 실행은 캐시로 답한다. 기준선과 심기
   실행이 같은 원자료를 보므로 차이는 심은 오류 때문이다. 대조군이 기준선과 다르면 그 종목은 "기준선 오류"(판정 불가).
5. 심는 값은 **명시값**이다. 앱 값이 목록의 `from` 과 다르면(앱이 바뀜) 심지 않고 "심기 실패"로 보고한다 — 목록을 갱신할 것.

## 3. 실행

```

node scripts/metrics/mutation.mjs                 # 전체
node scripts/metrics/mutation.mjs --only=M02a,M06b
node scripts/metrics/mutation.mjs --list          # 목록만
# 옵션: --base=URL · --no-external(외부 대조 끔 — ③ 검출 불가) · --cache=DIR(캐시 위치 지정·재사용 → SEC 요청 0, 지우지 않음) · --keep-cache(기본 캐시 보존 — 기본은 끝나면 지움, 7종목 약 0.7GB)
```

## 4. 오류를 목록에 추가하는 규칙

**앞으로 발견되는 실제 오류는 전부 심은 오류가 된다.** 고친 뒤에도 같은 유형이 돌아오면 검증기가 잡아야 하기 때문이다.

1. `MUTATIONS` 배열에 한 줄 추가: `id`(M+번호), `cat`(범주 — 새 유형이면 `CATEGORIES` 에 추가), `sym`·`col`, `what`, `origin`(실제
   사례·발견일·문서 위치), `expect`(잡아야 할 층 — A 원자료·B 결산기·C 화면 간·D 항등식·E 공시 정합성·F 외부), `plants`.
2. 심는 값은 그 종목의 **현재 앱 응답에서 확인한 값**을 `from` 으로, 실제로 틀렸던 값(또는 같은 크기의 오류)을 `to` 로 적는다.
   무작위·비율 계산 금지(재현성).
3. `node scripts/metrics/mutation.mjs --only=<id>` 로 돌려 "검출"인지 확인. 미검출이면 검증기를 고치거나, 오너 결정으로 §5 와
   목록의 `knownGap` 에 사유를 적는다.
4. 가로채기로 일관되게 재현할 수 없는 부분이 있으면 `countIf`(검출로 셀 검사 범위)와 `countNote`(사유)를 적는다 — 결과 "계측 메모"에 나온다.
