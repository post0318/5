## 1. 공통 데이터 모델

### 1.1 칸(cell)

칸 = **시장 · 종목 · 화면 · 지표(사전 행 ID) · 기간**이다. 이 다섯이 같으면 같은 칸이다.

| 필드 | 값 | 비고 |
|---|---|---|
| `market` | `us`·`kr`·`jp` | |
| `sym` | 종목 코드 | |
| `screen` | `hl` 하이라이트 · `an` 재무분석 · `ov` 개요 · `uv` 유니버스 · `cs` 컨센서스 · `is`/`bs`/`cf` 재무제표 · `isq`/`bsq`/`cfq` 분기·반기 | 화면 내용이 같으면 시장이 달라도 같은 화면 키를 쓴다 |
| `metric` | `01-metric-dictionary.md`의 행 ID(예 `hl.per`, `an.roe`). 재무제표 화면은 공시 계정 ID(`is:<accountId>`) | 사전에 없는 행은 칸으로 만들지 않고 「사전 밖 행」으로 보고한다(§3.6) |
| `period` | `FY2024`(결산일 연도) · `LTM` · `FY2026E`·`FWD12M` · `2025Q3`·`2025H1` | 결산일을 함께 적는다(`periodEnd`) |

칸 하나는 아래 값을 가진다.

```
Cell {
  key: { market, sym, screen, metric, period, periodEnd }
  A:  { v: number|null, blankReason: string|null, sourceLabel: string|null, fetchedAt }   // ② 앱 읽기
  E:  { v: number|null, blankReason: string|null,                                       // ④ 기대값
        status: "ok"|"lookup_failed",
        mode: "independent"|"common", commonReasons: string[],
        exceptions: string[],          // 적용한 ④′ 예외표 ID
        provenance: [{doc, line, vintage, unit}] }
  X:  [{ source, v, period, unit, definition, roundingUnit, fetchedAt, rawRef,          // ⑤ 외부값 정리
         defTag: "same"|"different:<사유>"|null }]
  rawVerdict:  "독립 일치"|"공통모드 일치"|"불일치"|"검증불가"                          // 가
  extVerdicts: { [source]: "일치"|"원인 확인"|"참고"|"외부 단독 이탈"|"미해결" } | "외부 없음"   // 나
  identity:    [{ check, status, peers }]                                              // ⑦
  final:       "통과"|"통과(외부 미확인)"|"외부 확인 통과"|"실패"|"미해결"|"공통모드"|"검증불가"  // 다
  why: string                                                                          // 사람이 읽는 사유 한 줄
}
```

- 값은 **API가 낸 원값**으로 비교한다(화면 표시 반올림 전 값). 표시 형식(%, 배, 소수 자리)은 ⑦ 표시 검사에서 따로 본다(§4.4).
- 결과를 다룰 때 「검사 행」이 아니라 「칸」 단위로 센다. 지금 검증기는 같은 칸을 여러 검사가 본다(예: DELL FY2022 EPS 한 칸에 A·C·E층 4행, 2호기 결과 파일). 그래서 행 수를 통과 수로 세면 부풀려진다.

### 1.2 수 비교 정의(세 시장 하나)

`exact(a, b)`:
- 둘 다 정수(원·엔·달러 금액, 주식수)이면 `a === b`일 때만 참이다.
- 그 밖(비율·주당값·환율 곱)이면 `|a − b| ≤ 1e-14 × max(|a|, |b|)`일 때 참이다. 같은 값을 다른 순서로 계산해서 생기는 부동소수 끝자리 차이만 허용한다는 뜻이다(`00-handoff.md` 가, VF:671 `SAME_FLOAT`).
- 한쪽이 0이면 다른 쪽도 정확히 0이어야 한다.

허용 오차는 이것 하나다. 시장별·층별 별도 허용치는 두지 않는다. 지금 코드에는 다른 값이 남아 있다(§8, 차이 D1~D4).

## 2. ④ 기대값 산출

### 2.1 입력 · 출력

- **입력**: ① 원자료 어댑터 출력만 받는다(공시 원본 사실 + 판본 + 단위·decimals + 문서 ID, 시세·주식수 원천 KRX·EDINET·SEC·Yahoo 시세). 형식은 `10-design-raw-adapters.md`를 따른다.
  ②(앱 응답)·③(외부 소스)·앱 DB(적재본 `kr_da`·`fin_sym`·`ttm_snap`·`universe_overview`)·앱 `src/` 파일은 **입력으로 받지 않는다**.
- **출력**: 칸마다 `E`(§1.1)를 낸다. 한 칸의 E는 값 또는 「빈칸 + 사유 종류」 하나이다. 원자료 조회가 실패하면 `status = lookup_failed`이고 값을 만들지 않는다.

### 2.2 독립성 규칙(공통모드 방지)

1. ④ 코드는 앱 코드(`src/**`)를 import하지 않고, 앱 파일을 `readFileSync`로 읽지도 않는다. 앱 데이터 파일도 포함한다.
   지금 이 규칙을 어기는 곳이 있다: `KR_CORP` = 앱 `src/lib/markets/kr/data/corpcodes.json`(VF:10856), 한국 휴장일 = 앱 `src/lib/macro/kr/market-calendar.ts`를 문자열로 읽음(`scripts/verify-kr/calendar.mjs:22`@KV).
   → 검증기는 DART `corpCode.xml`·KRX 휴장일을 ① 어댑터로 따로 받는다. 종목→고유번호 표는 공통모드 사유는 아니지만(틀리면 조회 실패로 드러남) 규칙 1에 따라 분리한다.
2. 앱 규칙의 「사본」(앱 표를 떠다 둔 JSON·상수)은 기대값에 쓰지 않는다. 사본으로 만든 E는 `mode = common`이다.
   예: VF:560 `IFRS_GROUPS_SNAPSHOT`, VF:571 `YAHOO_LTM_FIXED`, `scripts/metrics/cogs-rules.json`(AU:49 `COGS_RULE_COMMON`).
3. 앱 출력·앱이 붙인 메타데이터(출처 문구·LTM 항목 목록·빈칸 사유)로 기대값을 정하지 않는다. 이것들은 ⑦에서 「앱이 말한 것 = 검증기가 정한 것」을 대조하는 데만 쓴다(예: JL:356 열 출처 서류 대조는 대조로는 맞지만, 기대값 근거는 될 수 없다).
4. 시장 차이는 ④′ 예외표에만 둔다. ④ 본문에 `if (market === "kr")` 분기를 두지 않는다. 시장별로 다른 것은 ① 어댑터가 낸 「원천 줄」뿐이다.
5. `mode = common`으로 판정하는 경우(칸마다 사유를 `commonReasons`에 적는다):
   - (가) 앱과 같은 규칙 표·사본을 썼다(규칙 2).
   - (나) 앱과 같은 파생 데이터를 썼다. 예: Yahoo 분기 재무를 20-F LTM 원천으로 씀(AU:79 「Yahoo 분기 원천 공통」), Yahoo float 종가로 시가총액 계산(AU:82).
   - (다) 같은 추측 알고리즘을 따로 구현했다. 예: 본표 원가 판독 = 앱 `identifyCogs`와 같은 알고리즘(AU:86), 감가상각 줄 선택 정규식(AU:83), 판본을 「값이 단위 배수인가」로 추측(AU:92).
   - (라) 원자료 판독 규칙이 앱 수정과 같은 규칙이다. 예: 079550 리스부채 단위 「그해·이듬해 보고서 값이 1000^k 배로 갈리면 이듬해 값」은 앱 수정 d80b64c와 같은 규칙이다. 원문 주석의 「(단위: 천원)」 표기를 따로 읽어 확인하면 독립이다.

   공통모드 목록은 ④ 모듈 안에 **데이터로 한 곳**에 둔다(지금은 AU:51~100 `commonModeOf`가 검사 이름 정규식으로 추측한다 — §8 D9). 각 항목에는 「독립으로 바꾸는 방법」(독립 원천·독립 판독)을 함께 적고, 공통모드 칸 수를 매 실행 보고한다.

### 2.3 부품별 산출 규칙

정의는 지표 사전(초안 §2·§4 결정)을 그대로 따른다. 아래 표는 「무엇을 원자료에서 어떻게 계산하는가」와 「못 구하면 무엇을 내는가」만 정한다. 대체(그림자 채우기)는 없다. 못 구하면 빈칸이고, 사유 종류는 고정 문구 목록에서 하나를 고른다.

| 부품 | 산출(①만) | 빈칸 사유(고정) | 독립성 주의 |
|---|---|---|---|
| 기간 판정 | 결산일 = 공시 기간 끝(DEI·DART 보고서·EDINET 문맥). 연도 라벨 = 결산일 연도(52/53주 포함) | 「그 기간 공시 없음」 | 앱 연도 열을 보고 맞추지 않는다(VF 머리말 2026-09-24 WEN 사례) |
| 판본 | 최신 판본 우선. 같은 기간 값이 공시마다 다르면 decimals(공시 원본 정밀도)로 「반올림 재게시」와 「재작성」을 가른다(AU:233 `isDecimalsRounding`) | 「판본 판정 불가(decimals 없음)」 | 「값이 단위 배수인가」로 추측하면 공통모드(다) |
| 단위 | 사실의 unit·decimals + 원문 표 단위 표기. 이웃 해와 1000^k 배로 갈리면 원문 단위 표기로 정한다 | 「단위 판정 불가」 | 이웃 해 비교만으로 정하면 공통모드(라) |
| LTM 흐름 | FY + 당기 누적 − 전기 누적(분기 공시 시장 = 최근 4분기 합과 같음). 전기 누적은 **당기 보고서의 전기 열**(재작성 반영) | 「LTM 구성 값 없음(○○)」. 연간값으로 대체하지 않는다(A3) | 예외표 X-LTM-JP(반기), X-LTM-KR-35(3~5월 FY) |

| 순이익(지배) | 지배기업 소유주 귀속 순이익 줄(us-gaap NetIncomeLoss / ifrs ProfitLossAttributableToOwnersOfParent / EDINET 같은 요소) | 「지배 귀속 줄 없음」. 비지배 줄이 없고 연결 대상도 없으면 ProfitLoss = 지배로 둔다(사유 표기) | 한국 지금 앱 ProfitLoss(A1)와 갈린다. 의도된 불일치다 |
| ROA 분자 | 연결 순이익(ProfitLoss) | | 「ROA(연결)」(A1 결정) |
| 자기자본 | ① 지배주주 자본(PBR·BPS·ROE·재무레버리지) ② 자본총계(Q1: 한국 부채비율 계열) | 「지배 자본 줄 없음」 | 예외표 X-EQ-Q1 |

### 2.6 시험 방법

1. **원자료 흔들기(독립성 시험)**: ① 캐시의 원자료 사실 하나를 바꾸고 ④를 다시 돌린다. 그 사실에 기대는 칸의 E가 **바뀌어야** 한다. 앱 응답은 그대로이므로 그 칸은 불일치가 되어야 한다. E가 바뀌지 않으면 그 E는 원자료가 아닌 곳에서 온 것이므로 결함이다. ⑨ S-R 계열(§6.3)로 돌린다.
2. **앱 응답 무관 시험**: ② 입력을 비우거나 다 0으로 바꿔도 E 출력의 해시가 같아야 한다(④는 ②를 보지 않음).
3. **정적 검사**: ④ 디렉터리에서 `src/` 경로 문자열·`import … from "../src"`·`readFileSync(.*src/` = 0건. `market ===` 분기 = 0건(예외표 조회 함수만 허용). no-undef 0건(`feedback-verifier-precheck`).
4. **손계산 표본**: 시장별 부품마다 2칸 이상, 측정 문서에 이미 손계산이 있는 칸을 정답으로 쓴다(예: 삼성전자 LTM 시가총액 1,356,336,637,056,000원 `04`, 엘에스일렉트릭 FY2025 이자 52,196 `06`, 대한전선 FY2022 PER 손계산 `07`, 信越 현금 `08`).

## 3. ⑥ 비교·판정

### 3.1 입력 · 출력

- **입력**: 칸마다 A(②), E(④), X 목록(⑤ — 각 외부값의 기간·단위·표기 반올림 단위·정의 표시 `defTag`).
- **출력**: `rawVerdict`·`extVerdicts`·`final`·`why`(§1.1). ⑥은 **순수 함수**이다(네트워크·파일 없음). 칸 하나를 받아 판정 하나를 낸다. 지금 AU가 순수 함수로 떨어져 있는 것과 같은 방식이다.

### 3.2 가. 원자료 판정(결정표)

위에서부터 처음 맞는 줄 하나를 쓴다.

| # | 조건 | rawVerdict | why |
|---|---|---|---|
| 가1 | `E.status = lookup_failed` | 검증불가 | 「원자료 조회 실패: …」 |
| 가2 | E 빈칸 · A 빈칸 · 사유 종류 같음 | 일치(빈칸) → `E.mode`에 따라 **독립 일치/공통모드 일치** | 「기대 빈칸 — 사유」 |
| 가3 | E 빈칸 · A 빈칸 · 사유 종류 다름(또는 A 사유 없음) | 불일치 | 「빈칸 사유 다름: 기대 ○○ / 앱 △△」 |
| 가4 | E 값 · A 빈칸 | 불일치 | 「원자료 E 있는데 앱 빈칸」 |
| 가5 | E 빈칸 · A 값 | 불일치 | 「기대 빈칸(사유)인데 앱 값」 |
| 가6 | `exact(A, E)` | `E.mode` = independent → 독립 일치 / common → 공통모드 일치 | |
| 가7 | 그 밖 | 불일치 | 「앱 A vs 기대 E (차 A−E)」 |

- 가2·가3에서 빈칸 사유 대조를 넣은 것은 **가설을 구체화한 제안**이다. 가설 원문은 「기대 빈칸·A 빈칸 → 일치」이다. 근거: 한국 감사 11차에서 「기대 빈칸이면 사유가 아무 문자열이어도 통과」가 결함으로 드러났고(KL:77 주석), 화면에 사유를 보이는 것이 그림자 채우기 금지의 짝이다. 사유 대조는 「종류」(고정 문구 목록의 ID)로 하고 문장 전체를 비교하지 않는다. → **미결(오너 확인) M1**.
- 공통모드 일치는 통과가 아니다. 다의 규칙으로만 풀린다.

|---|---|---|
| 나0 | 그 칸에 외부값이 하나도 없음 | (칸 전체) **외부 없음** |
| 나1 | ⑤에서 `defTag = different:<사유>`(정의가 다르다고 표시됨 — 기간·범위·주식수 정의) | **참고**(판정에 쓰지 않음, 사유 기록) |
| 나2 | 같은 기간·같은 정의 · `exact(A, X_s)` | **일치** |
| 나3 | 같은 기간·같은 정의 · `round(A, 표기 단위) = X_s`(표기 반올림 안에서만 같음) | **변형 V1(가설)**: 일치 / **변형 V2(09-26 오너 결정)**: 검증불가(외부 정밀도 부족) — 독립 근거 아님. → **미결 M2** |
| 나4 | 차이가 원자료 줄로 만든 식으로 **모든 해에 정확히** 성립(예: X = A − 비지배지분, X = A − 리스 이자) | **원인 확인**(식·쓴 줄을 기록) |
| 나5 | 가 = 독립 일치이고, **다른 독립 외부 k곳 이상**이 앱과 정확 일치(나2)이며 이 소스만 다름 | **외부 단독 이탈** |
| 나6 | 그 밖 | **미해결** |

- 나4의 식은 「이름 붙이기」로 성립시키지 않는다. 외부 사이트 줄을 원자료 줄과 하나씩 맞춰 숫자가 정확히 성립할 때만 인정한다(`feedback-definition-diff-needs-decomposition`). 식에 쓴 값이 앱 값이면(예: 앱 비지배지분을 그대로 믿음) 원인 확인이 아니다. 식의 항은 ① 원자료나 다른 독립 외부값이어야 한다(VF:11383 주석 「앱 nci를 그대로 믿으면 nci 오류를 정당화」와 같은 원칙).
- 나5의 k: 가설 원문은 「다른 독립 외부는 앱과 정확 일치」(곳 수 없음), 지금 결정·코드는 지표마다 다르다. 매출·매출원가·영업이익·감가상각·판관비는 09-25 오너 결정(`project-financial-architecture`)대로 **2곳 이상**이다(VF:10539·10566). 희석 EPS·순이익·세전이익·EBITDA·총차입금·재무상태표·현금흐름표는 오너 결정 09-30에 따라 **다른 외부 1곳 이상 일치, 또는 원인 확인·정밀도 검증불가 1곳**이면 외부 단독 이탈이다(VF:10587~10588). 같은 곳에서는 A층이 공통모드여도 외부 1곳이 일치하면 전제를 인정한다(VF:10583 `aCommonOk`). → 측정 변형 K1·K2(§7.3), **미결 M3**.
- 지금 분류 중 새 표에 없는 것이 있다. 「외부 정의 분해 불가」(VF:10567, 오너 결정 09-27), 「환율 영향(보류)」(VF:10559), 「A층검증불가」(VF:10571)이다. 새 표에서는 모두 **미해결**로 둔다. 「외부 정의 분해 불가」를 참고로 둘지는 **미결 M4**이다(09-27 결정과 handoff 「정의 다름은 ⑤에서 표시된 것만 참고」가 갈림).
- 공통모드 소스: 외부 소스가 앱과 같은 원천일 때(예: 앱 20-F LTM = Yahoo 분기, 외부 Yahoo LTM)는 ⑤에서 `defTag = different:same-origin`으로 표시한다. 그러면 나1 참고로 가고, 독립 외부 곳 수에 세지 않는다.

`ext` = 나 결과 묶음. 「미해결 있음」 = 소스 중 하나라도 미해결. 「독립 정확 일치 n곳」 = 나2(V2면 나3 제외) 소스 수.

| 다1 | 불일치 | (무관) | **실패** | 차단 |
| 다2 | 검증불가 | (무관) | **검증불가** | 차단(조회 실패는 재실행 대상) — **미결 M6** |

| 다4 | 독립 일치 | 외부 없음 | **통과(외부 미확인)** | 완료 보고에서 뺀다(별도 목록) |
| 다5 | 독립 일치 | 그 밖(일치·원인 확인·참고·외부 단독 이탈만) | **통과** | 포함 |

- 지금 코드와 다른 점: AU:165~167 「Yahoo 1순위 · 외부 한 곳이라도 ①·②면 통과 — 나머지 소스의 미규명 차이는 사유에만」. 새 정의에서는 다른 소스가 미해결이면 그 칸이 미해결이 된다(다3). 「Yahoo 1순위」(09-27 오너 결정, 멀티플 비교점)는 판정 우선순위가 아니라 화면 비교점 표시로만 남길지 → **미결 M4에 포함**.

### 3.5 사례(측정 문서·2호기 결과 파일의 실제 값)

새 ④ 규칙으로 E를 다시 계산한 값은 아직 없다. 아래에서 「E(새 규칙)」는 측정 문서의 손계산이나 결정 산식으로 정한 값이다. 재생(§7)에서는 이 칸들을 정답 표본으로 쓴다.

**예 1 — 삼성전자 LTM 시가총액(한국, 하이라이트, 2026-10-13)** (`04`)
- A = 1,356,336,637,056,000원. E = KRX 종가 232,000 × 상장주식수 5,846,278,608 = 1,356,336,637,056,000원(KRX 직접 조회, 독립).
- 가6 → 독립 일치.
- X: FnGuide 13,563,366억(억 반올림), 네이버 1,356조 3,366억. 둘 다 round(A, 1억) = X. 나3 → V1이면 일치 2곳, V2이면 검증불가(정밀도) 2곳.
- 다: V1 다5 **통과** / V2 다5에 일치 소스 0곳(참고·정밀도만) → M1 제안대로면 **통과(외부 미확인)**.
- → 한국 외부 원천(FnGuide 억원·네이버 조·억)은 거의 모두 표기 단위가 커서, M2 결정이 한국 완료 보고 칸 수를 크게 바꾼다. 측정에서 숫자로 보인다(§7.4 표 R3).

**예 2 — DELL FY2022 기본 EPS(미국, 하이라이트)** (결함 A23)
- 지금 결과(`verify-us-20261011-090005.json`): 「기본 EPS 앱 = SEC 공시 기본 EPS(분할 보정)」 pass, note 「공시 기본 EPS 없음 → 앱 빈칸」. 희석 EPS는 「계속영업 6.26 + 중단영업 0.76 희석 EPS(총 EPS 태그 없음)」으로 7.02 pass.
- 새 ④: 기본 EPS 사슬 = 공시 기본 전체 → 없으면 계속 기본 + 중단 기본(§2.3). 10-K에 계속·중단 기본 EPS가 있으면 E = 그 합이고, A = 빈칸이다.
- 가4 → 불일치 → 다1 **실패**.
- → 판정 규칙(가·나·다)만 바꿔서는 못 잡는다. ④의 기대값 사슬이 앱과 같은 「없으면 빈칸」이었던 것이 원인이다(공통모드 (가) 유형이 공통모드로 표시되지도 않은 사례). 재생(§7)은 이 칸을 「④가 필요한 알려진 오류」로 따로 센다.

**예 3 — 079550 LIG디펜스앤에어로스페이스 FY2024 리스부채 → 총차입금·EV(한국)** (커밋 d80b64c, 10-05)

**예 5 — 두산에너빌리티 FY2025 배당성향(한국, 재무분석)** (`07` §D)

### 3.6 실패 처리

- 사전에 없는 화면 행(②가 낸 행이 사전 ID에 매핑되지 않음) → 칸을 만들지 않고 「사전 밖 행」 목록에 올린다. 0이 아니면 실행 요약에서 경고하고 완료를 막는다(화면이 사전보다 앞서 바뀐 것).
- 사전 행인데 ②에 행이 없음 → A = 빈칸(사유 「행 없음」)으로 칸을 만든다. E가 있으면 가4 불일치이다.
- ⑥ 함수 예외 → 그 칸 「검증기 오류」 → 실행 종료코드 1. 칸 판정을 조용히 비우지 않는다.

### 3.7 시험 방법

1. **결정표 전수 시험**: 가1~가7 × 나0~나6 × 다0~다8 조합을 합성 칸으로 만들어(값·mode·defTag·소스 수 경계 0/1/2/3) 표대로 나오는지 본다. 경계 칸은 정수 ±1, 소수 ×(1 ± 1e-14), ×(1 ± 2e-14), 0과 −0이다.
2. **변형 스위치**: M2(V1/V2)·M3(k, c)를 설정값으로 받는다. 측정 뒤 확정값 하나로 고정한다(설정값을 운영 중에 바꾸지 않는다).
3. **옛 결과 재생**(§7)과 **심은 오류**(§6).

## 4. ⑦ 화면 간·항등식

### 4.1 입력 · 출력

- **입력**: ② 앱 값 칸 전체(같은 종목·기간), 사전의 「같은 값 묶음」·「항등식」 정의.

### 5.3 보고 형식(`report.md`, 오너용)

`feedback-no-false-assurance` 3단을 따른다. 「이상 없음·완료·문제없음」 같은 단정어는 쓰지 않는다.

2. **발견**: 실패·미해결·검증불가·공통모드 칸 목록. 칸마다 `why` 한 줄 + A·E·X 값을 적는다. 같은 원인으로 묶어 원인별로 보여 준다(예: 「A1 지배 순이익 — 30종목 150칸」).
3. **못 본 범위**: 통과(외부 미확인) 칸 수와 목록 위치, 공통모드 칸 수, 외부 없음 칸, 사전 밖 행, 표본 밖 종목, 심은 오류 목록에 없는 유형.

### 5.4 완료 보고 규칙

- **완료 보고에 넣는 것**: final = 통과 · 외부 확인 통과뿐이다.
- **완료 보고에서 빼는 것**: 통과(외부 미확인). 「외부 미확인 N칸」으로 따로 적는다(가설 다 「완료 보고 제외」).

## 6. ⑨ 심은 오류 시험(세 시장 공통)

### 6.1 방법

- **심는 곳 세 가지**:
  - (a) **앱 응답(②)** — 검증기 쪽 fetch 가로채기로 넣는다(지금 MU 방식, 앱·DB는 건드리지 않음).
  - (b) **원자료 캐시(①)** — 독립성 시험(§2.6-1)에 쓴다.
  - (c) **외부 응답(③)** — 나 경로 시험에 쓴다.
- **기준선·대조군**: 종목마다 심기 없는 기준선 1회 + 캐시로만 다시 돈 대조군 1회(MU:33 `CONTROL`). 대조군이 기준선과 다르면 재현성 문제로 보고 검출 판정을 하지 않는다.
- **검출 정의**: 심은 칸(또는 지정된 관련 칸)의 final이 기대 상태(아래 표 「기대」)로 새로 바뀌는 것이다. 통과·외부 확인 통과·공통모드·검증불가로 가면 미검출이다. 기대 상태가 아닌 다른 차단 상태(예: 실패를 기대했는데 미해결)는 「검출, 경로 다름」으로 따로 센다.
- **심는 값 명시**: from → to로 적는다. 앱 값이 from이 아니면 「심기 실패」로 보고하고 심지 않는다(MU 규칙 유지).
- **목록 추가 규칙**: 실제로 발견되는 오류는 모두 한 줄로 추가한다(MU 머리말과 같음). 세 시장 중 해당 시장이 없으면 「해당 없음(사유)」을 적는다.
- **2호기 부하**: 종목 수 = 시장당 대표 5~7종목. 검증기 동시 1개, 시작 전 `free -m` available 2GB 이상(`feedback-verify-server-memory`).

## 7. 판정 규칙 측정 계획(전체 진행 ④단계)

목적은 가설 판정 정의(가·나·다)를 지난 결과에 다시 적용해서 **문턱(M2 표기 반올림, M3 외부 단독 이탈 k·공통모드 해제 c)을 숫자로 정하는 것**이다. 앱·검증기 코드는 바꾸지 않는다. 결과 JSON을 읽기만 하는 재생 스크립트 하나를 2호기 스크래치(`~/verify-common-measure/`)에 둔다. 측정 문서로 남기고, 스크립트는 커밋하지 않는다(03~08 측정과 같은 방식).
**2호기에서만 할 수 있다**: 결과 파일(17.6MB 등)과 로그가 2호기 디스크에만 있고, 클라우드 세션은 2호기 접근이 없다. 외부 요청은 0건이다(이미 받은 결과만 읽음).

### 7.1 입력(2호기에서 10-14에 확인한 사실)

### 7.2 절차

1. **사본**: 위 파일을 `~/verify-common-measure/in/`에 복사하고 md5를 기록한다. 원본은 건드리지 않는다.
2. **검사 행 → 칸 대응표**: `(market, layer, name 정규식, col) → (screen, metric, period)` 표를 데이터 파일로 만든다. 대응되지 않은 행은 수와 이름 상위 목록을 보고한다. 목표는 「값 대조 행」 100% 대응이다. 구조 검사(행 존재·응답 수신 등)는 칸이 아니라 「실행 점검」으로 따로 센다.
3. **가 재구성**(칸마다 그 칸의 원자료 대조 행들로):
   - `pass` → 독립 일치. 단 `commonModeOf`(AU:51) 사유가 있는 행이면 공통모드 일치.
   - `common` → 공통모드 일치.
   - `fail` → 불일치.
   - `unverifiable` → note로 가른다: 「조회 실패·판독 불가」 → 검증불가, 「양쪽 빈칸」 → 일치(빈칸)(사유 대조는 옛 결과에 없어서 가2 = 가3 구분 불가 — 그 수를 따로 센다).
   - 한 칸에 원자료 대조 행이 여럿이면 하나라도 fail → 불일치, 아니면 하나라도 common → 공통모드.
4. **나 재구성**(외부 대조 행 `review`의 `sources`·`ours`로 소스마다 다시 계산):
   - `exact(ours, v)` → 일치.
   - 아니면 `round(ours, 표기 단위) = v` → 나3(변형별). 표기 단위는 VF F층 표(소스·지표별)를 그대로 쓴다.
   - `causes[s].ok` → 원인 확인. 단 식의 항에 앱 값이 들어간 원인 규칙(VF:11383 한국 EV nci 등)은 「원인 확인(앱 값 사용)」으로 따로 센다.
   - `causes[s].common` → 참고(같은 원천).
   - 외부 단독 이탈 → 나5를 k 변형별로 다시 판정한다(옛 분류를 그대로 쓰지 않는다).
   - 그 밖(③·외부정의분해불가·환율영향·A층검증불가) → 미해결. 단 M4 변형으로 「외부정의분해불가 → 참고」도 같이 센다.
5. **다 계산**: 변형 조합(§7.3)마다 final 분포를 낸다.
6. **알려진 오류 대조**(§7.4 R5).
7. **⑦ 실측**: 미국 결과의 화면 재계산 행 중 ROE·순이익률·회전율·레버리지 칸이 같은 열에 다 있는 경우, I3 듀폰 식을 그 앱 값으로 계산해 상대 차 분포를 낸다(1e-14 안 비율). 앱 값은 결과 JSON의 `app` 필드에 있을 때만 쓰고, 없으면 「값 없음」으로 센다(앱을 다시 부르지 않는다).
