## 2. 설계와 다르게 한 것(이유)

1. **옮기기 = 하드링크**(설계 「rename」). 앱 코드가 아직 옛 폴더 배치를 읽어서, 옮기면 앱 캐시가 깨진다. 같은 디스크라 하드링크도 공간이 더 들지 않는다. 옛 폴더 삭제는 앱이 새 루트로 바뀐 뒤(순서 4) — 앱 브랜치 작업.
2. **형식·신원이 틀린 기존 파일은 격리하지 않고 들여오지만 않았다** — 원래 파일은 앱이 쓰고 있어 옮길 수 없다. 결과 파일에 사유를 남겼다(이번 실행 거부 0).
3. **SEC HTML 은 바이트가 받을 때마다 다르다**(끝의 봇 차단 스크립트 경로). 그 한 줄만 다르면 같은 원본으로 본다(`equivalentFor`, 사고 기록 `equivalent_bytes`).
4. **DART 보고서 응답의 신원**: 판본 = 목록의 최신 접수번호인데, 재무를 다시 싣지 않은 정정이면 행의 접수번호가 원 보고서(더 이른 번호)다 → 「판본 이하」로 확인.
5. **EDINET 목록의 신원** = 응답 `metadata.parameter.date`(ファイル日付 — 그날 정정·취하된 옛 서류도 실려 제출일로 확인하면 틀린다).
6. **신원 표지가 없는 파일**(일반 HTML 첨부, 6-K 본문)은 형태 검사만 — 결과 `got: "no-identity-marker"`.
7. **하루 상한 카운터 위치** = 보관소 안(`quota/`) — 여러 작업트리·실행이 같은 날 합계로 센다. 옛 한국 검증기 카운터(`reports/.dart-quota`)와는 따로다(옛 검증기를 거두면 하나).

이번에 고친 판독 결함(T4·골든이 찾음):
1. **일본 손익·포괄손익 한 표**(丸紅 8002 「連結包括利益計算書」 하나에 손익까지) — 역할 이름만으로 포괄손익(ci)으로 분류해 연결 매출이 본표에서 빠졌다. 같은 연결 범위에 손익 역할이 없고 그 역할에 매출·당기순이익 줄이 있으면 손익으로 본다(`jp/read.mjs`).
2. **일본 연결 매출·금융 서식 개념 누락** — 사슬에 `jpigp_cor:Revenue2IFRS`(상사 収益)·`OrdinaryIncomeBNK/INS`(経常収益, D34)·`OperatingRevenueSEC`, 현금에 `CashAndDueFromBanksAssetsBNK` 추가.
3. **일본 연결 우선 위반** — 연결 본표가 있는 서류에서도 별도(개별) Item 을 내, 대조기가 연결 값이 없을 때 지주사 개별 값(8306 営業収益 809,818)을 집었다. 어댑터가 연결 본표 있는 서류의 별도 Item 을 내지 않게 하고, 대조기(t4-jp)도 별도 값으로 대신하지 않게 했다 — 연결 개념이 빠지면 칸이 빈칸으로 드러난다.
4. **한국 이자 DIE 「보고 금액」 차원** — HD현대중공업 FY2023·24 금융원가 주석 칸(131,890·149,669)은 `CarryingAmount…Axis = dart:ReportedAmountMember` 차원이 붙어 있어 버려지고, 차원 없는 범주별 표 칸(128,411·98,006)만 남았다. 그 차원은 기본 칸으로 보고, DIE 가 여럿일 때의 기존 규칙(원문 금융원가 표로 선택)이 고른다(`kr/interest.mjs`).
5. **같은 결함 — 한국 리스부채 주석 후보**(같은 종류 전부 점검): 보관된 사업보고서 XBRL 216건 중 이자 DIE·리스부채가 「보고 금액」 차원에만 달린 보고서 77건. 리스부채 후보도 그 차원을 기본 칸으로 본다(`kr/adapter.mjs`). 30종목 전후 비교: 010120·178320 에서 놓치던 주석 값이 새로 잡힘, 기존 값 변경·새 모호 0.

설계와 다르게 둔 것(이유):
- **조회 실패는 실행 단위 failures 에 남고, 그 서류의 Item 은 만들지 않는다**(설계 §3.4 「빈칸 + 사유」와 다름). 조회가 실패하면 어떤 칸이 있어야 하는지 자체를 모른다(서류를 못 읽었으므로) — 칸을 지어 내지 않고 ⑥ 이 그 종목·서류의 failures 를 검증불가(종료코드 1)로 센다. 이자처럼 칸이 정해진 항목은 빈칸 + fetch_failed.
- 감사 중 EDINET 신원 판정을 처음 잘못 넣어(半期 = q2r 를 몰랐음) 정상 半期 80건이 격리되고 다시 받았다(외부 요청 160 + 80, 무료). 두 번째 실행 0 확인.
