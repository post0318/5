여러 소스(증권사 수집 스크립트 등)가 같은 패턴의 코드를 각자 복사해 쓰고
있을 때, 하나에서 버그를 발견해 고치면 **그 자리에서 바로 나머지 전체를
감사(grep)해서 같은 버그가 있는지 확인하고 한꺼번에 고쳐야 한다.** 사용자가
종목별로 하나씩 다시 확인하며 버그를 재발견하게 만들면 안 된다.

**Why:** 2026-09-13 세션에서 "목표주가 조사(를/는/가) 미처리" 버그를 KIS
하나에서 발견해 고쳤는데, 같은 패턴을 하나·한화·신한·NH·유안타에도 그대로
복붙해 썼다는 걸 나중에야 감사해서 알았다. 사용자가 "언발란스하게 미스나는
것을 공통으로 적용한다"고 명시적으로 지적했고, 그 전에 이미 "한 번에 제대로
했으면 한다. 이게 몇번째냐", "효율화를 위해 하는데 하루를 여기에 쓰고
있다"며 반복 수정에 강하게 지친 기색을 보였다.

**How to apply:**
- 여러 파일이 같은 로직을 복붙한 구조(이 프로젝트의 `scripts/collect-*-
  research.mjs`가 대표적 — 각 증권사별 스크립트가 유사한 정규식/헬퍼를
  독립적으로 들고 있음)에서 버그를 고칠 땐, 고친 직후 `grep`으로 같은
  정규식/패턴을 쓰는 다른 파일을 전부 찾아 감사한다.
- 감사 결과를 사용자에게 먼저 보고하고("N개 파일에서 같은 패턴 발견,
  전부 고치겠습니다") 한 번의 커밋으로 묶어 고친다 — 하나 고치고 배포,
  또 하나 발견하고 배포를 반복하지 않는다.
- 백필처럼 시간이 걸리는 검증 작업도 "이 종목만" 확인하지 말고 여러
  대표 종목·소스를 한 번에 교차 확인해서 문제를 한 라운드에서 최대한
  걸러낸다(이 세션 후반부에 실제로 HD현대중공업·삼성전자·효성중공업·
  LG에너지솔루션 4종목을 동시에 조회해 문제를 훨씬 빨리 찾아냈다).
