목표주가·투자의견처럼 "리스트나 API 응답에 값이 있다"는 사실만으로 그 값을
바로 화면에 보여주면 안 된다. 그 값이 **해당 리포트 본문에 실제로 언급된
값인지** 확인한 뒤에만 표시해야 한다.

**Why:** KB증권 API의 `tp`(목표주가)·`recomm`(투자의견) 필드가 실제로는
"그 종목에 대해 KB가 현재 유지 중인 값"이라 컨퍼런스콜 후기 같은 리포트에도
항상 채워져 있었다 — 그 리포트 본문엔 목표주가 언급 자체가 없는데도 화면엔
"매수 600,000원"이 표시되는 버그로 발견(오너가 실제 PDF 링크 2건을 주며
"이 리포트는 투자의견이 없는데 매수는 어디서?"라고 지적, 2026-09-13). 한경
컨센서스의 "적정가격"/"투자의견" 컬럼도 같은 위험이 있어 동일하게 본문
검증을 추가했다.

**How to apply:** 어떤 소스든 "목록/API에 값이 있다" ≠ "그 리포트가 그 값을
말했다"라고 가정하고 접근한다. 구체적으로:
1. 이미 본문(PDF·상세페이지·리스트 요약)을 다른 목적(발췌 등)으로 받고
   있다면, 그 본문에 해당 라벨("목표주가"/"투자의견" 등)이 실제로 등장하는지
   정규식으로 확인한 뒤에만 메타데이터 값을 채택한다.
2. 본문에 없으면 값을 `null`/빈 문자열로 두는 게 정상이다 — 억지로 채우지
   않는다(오너 직접 확인: "그게 정상이다").
3. 반대로 본문에는 있는데 목록/메타데이터가 비어있는 경우(예: 하나증권 PDF
   표지에만 있고 목록 요약엔 없음)는 본문을 폴백으로 파싱해서 채운다 —
   "목록/표를 우선하되 없으면 본문/PDF로 보강"이 오너가 확정한 순서.
4. 목표주가 정규식은 "목표주가**를/는/가**"처럼 조사가 붙는 문장체와
   "목표주가 (유지)"처럼 라벨 뒤에 괄호 주석이 붙는 헤더체를 둘 다
   허용해야 한다 — 미래에셋만 조사를 처리하고 있었고 나머지는 안 돼서
   실제 값이 있는데도 못 뽑는 버그가 여러 소스에서 반복됐다.
