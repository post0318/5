재무 검증·수정은 결함이 보일 때마다 부분 수정하지 말고, **지표 하나를 모든 조합에서 한 번에 정의·구현·검증·감사해 닫은 뒤** 다음 지표로 간다. 닫은 지표는 다시 열지 않는다(뒤 작업의 영향은 회귀 검사로).

**Why:** 오너 지적 2026-09-25 — "했던거 또하고… 한번에 처리할 수 있는 건 한번에 처리해야… 매출이면 매출부터 다 통일시키거나. 과거든 LTM이든 20-F든 10-K든 GAAP든 IFRS든… 사용은 늘어나는데 깔끔하게 마무리되는 거 없다." 또 "내가 말한 것만 생각하잖아 6-K도 있다며?" — 오너가 예로 든 차원만 옮기지 말고 **내가 아는 차원을 빠짐없이** 스스로 목록화할 것.

**How to apply:** 순서 = 손익계산서 항목 순(매출 → 매출원가·매출총이익 → 판관비·R&D → 일회성비용 → 영업이익 → 이자·영업외·지분법 → 세전이익 → 법인세 → 순이익 → EPS) → 현금흐름표(영업CF, 감가상각비·EBITDA, CapEx, FCF, 배당·자사주) → 재무상태표(현금·단기투자, 차입금·리스, 자본, 자산, 주식수) → 파생(시가총액·EV·멀티플). 각 지표마다 차원 체크리스트 전 칸 현황표 → 결정 사항 일괄 질문 → 한 모듈 수정 → 47종목 전 기간 검증·외부 차이 전부 분해 → 독립 감사로 닫기. 차원: 공시(10-K/10-Q, 20-F/40-F, 6-K, 8-K 재작성, DEF 14A 오염), 기준(GAAP/IFRS/회사 고유 태그), 원자료 형태(표준 태그·인스턴스·계산 구조·차원 멤버·옛 제출 형식·태그 중단), 정정(재작성·반올림 재태깅·단위 오류·분할/분사), 기간(연간 52/53주·분기·누적·LTM·중단사업), 통화(USD·외화·ADR 비율), 회사유형(일반·금융·리츠·금융자회사·복수클래스·DART 연결 ADR), 외부(Yahoo·StockAnalysis·인포맥스·Finviz·인베스팅). 관련: [[feedback-batch-fix-then-verify]], [[project-verification-order]]
