재무 검증 작업에서 발견된 결함은 **전부 고친 다음** 전체 재검증(유니버스)과 독립 감사를 **한 번만** 돌린다. 수정 중에는 해당 종목·회귀 확인용 몇 종목만 빠르게 확인한다.

**Why:** 오너 지적 2026-09-24 — "결함이라고 나온 것을 고치고 난 뒤 다시 재검증과 독립감사를 받아야지 이건 머 건건이 하니깐 속도가 안나오는 것 같다." 하루 종일 수정 → 전체 재검증(약 20분) → 감사를 건별로 반복해 진도가 느렸다.

**How to apply:** 결함 목록을 먼저 모으고, 파일이 겹치지 않는 수정은 병렬 에이전트로 동시에 진행한다. 모두 끝나면 전체 재검증 1회 → 독립 감사 1회 → 새 미해명 목록으로 다음 라운드. 관련: [[feedback-exact-match-verification]], [[project-verification-order]]

**재위반 기록(2026-09-26~27)**: 스냅샷(전후 비교)은 "검증이 아니다"라고 스스로 구분해 수정마다 61종목 스냅샷(약 20분)을 떴고, 47종목 전체 검증도 수정 때마다 반복했다. 오너 — "전체 검증은 1번만 하라고 이미 규칙 정하지 않았나? … 스냅샷은 매번 했다는 건데 오너 지시 무시하고". **스냅샷·전체 검증·골든셋 대조·심은 오류 시험 모두 "전체 실행"에 포함** — 지표를 닫을 때 1회. 수정 중엔 해당 종목만(스냅샷도 --symbols 로 해당 종목만).
