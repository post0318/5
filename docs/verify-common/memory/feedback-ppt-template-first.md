이전 PPT 기능(PptxGenJS, 2026-09 삭제)은 사내 템플릿(11.69×8.27", 기존 표·차트·이미지 객체)을 보존하지 않고 10×7.5" 새 슬라이드를 다시 그렸고, 들어간 숫자(예상 매출·EPS·PER)의 출처·산식 연결이 불명확했다. 오너가 외부 리뷰와 함께 "반성해라"(2026-09-26), 이전에 "전반적으로 문제가 있다. 첨부터 다시할거다".

**Why:** 앱의 핵심 문제(앱 숫자 ≠ 공시 ≠ 다른 사이트)를 PPT가 그대로 반복했다. 오너는 내 코드를 신뢰하지 못하는 상태 — 완료 보고가 검증보다 앞섰던 이력 때문.

**오너 결정(2026-09-26): PPT 는 챗GPT 를 활용하는 독립 모듈로 만든다** — 이 앱(Claude 코드)에 PPT 생성 코드를 다시 넣지 않는다. 내 몫은 앱 쪽에서 검증된 확정 데이터를 출처와 함께 내보내는 인터페이스(JSON)까지. 요청 없으면 PPT 생성 로직을 만들지 않는다.

**How to apply:** (독립 모듈 설계에 의견을 줄 때도 같은 기준) PPT 재개 시 ① 코드 전에 템플릿 영역(텍스트·표·차트 객체·이미지) 식별표를 먼저 보여 승인받기 ② 템플릿 파일을 복제해 기존 객체의 내용·차트 데이터만 교체(새로 그리지 않음) ③ 입력은 재무 검증을 통과한 확정 데이터(JSON)만, PPT 생성기는 판단·계산·외부 조회 없음, LLM 이 숫자를 만들지 않음, 시장점유율 등 외부 자료는 출처·기준시점 있는 것만 ④ 생성된 pptx 를 다시 파싱해 숫자 = 입력 JSON 을 기계적으로 대조한 결과 없이 완료라 하지 않기. 재무 확정 데이터가 먼저다 — [[project-financial-architecture]], [[feedback-exact-match-verification]]
