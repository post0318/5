재무 숫자 검증(verify-financials 등)에서 허용치(%)를 좁히는 방식으로 보강하지 말 것. 원자료 기준으로 계산한 값과 **완벽히 일치**해야 통과이고, 틀리면 그 차이의 원인을 찾아 수정·설명까지 마무리한다.

**Why:** 오너 지시 2026-09-24 — "허용치를 좁히는 것보다 완벽하게 일치해야한다. 틀리면 그 차이를 찾아서 마무리해야한다." 허용치는 오류를 숨긴다(감사에서 TRV 7.7%, 리츠 12% 오류가 25% 허용치로 통과한 사례).

추가 지시(같은 날): "단순히 한곳만 일치한다고 통과하고 그러면 안된다." — 외부 소스 하나와 맞았다고 통과 처리 금지. 사용 가능한 모든 소스(SEC 원자료 계산값 + Yahoo·StockAnalysis·인포맥스, 국내 DART + FnGuide·네이버)와 교차 대조하고, 소스 간 차이마다 원인을 밝혀야 통과.

한국도 같은 원칙(오너 지시 2026-09-24 밤 — "한국도 fnguide만 믿을수는 없기에 야후와 인베스팅닷컴까지 대조군에 포함한다"): 국내 외부 대조군 = FnGuide + Yahoo(.KS/.KQ, 스크립트) + 인베스팅닷컴. 인베스팅닷컴은 스크립트 접근이 403(봇 차단)이라 우회하지 않고 브라우저 개별 확인으로만 대조.

핵심 원칙(오너 지시 2026-09-25 — "MD 핵심은 숫자의 오차가 없어야 한다이다. 정의의 차이가 아닌 수의 차이는 심각한 오류의 결과이다"): 모든 차이는 ① 일치 ② 정의 차이(특정 항목으로 숫자 분해가 정확히 성립) ③ 오류 중 하나다. 분해되지 않는 차이는 "미해명"이 아니라 **심각한 오류**로 다루고, 앱·외부 어느 쪽 오류인지 숫자로 증명해 닫을 때까지 그 지표를 닫지 않는다. 외부 데이터 오류도 숫자로 증명돼야 외부 오류로 분류. 지표 정의 문서(md) 맨 앞에 이 원칙을 둔다.

**How to apply:** 검증 항목 설계 시 기준값을 SEC/DART 원자료로 독립 계산하고 정확 비교. 외부 사이트(정의가 다른 소스) 대조는 검토 목록이지만, 차이가 나면 원인(정의 차이/우리 버그)을 규명해 기록할 때까지 미결로 둔다. 관련: [[feedback-verify-before-display]]

외부 비교 허용 오차도 금지(오너 2026-09-26 — "허용오차는 허락한적이 없는데"): 외부 소스 표기 단위(인포맥스 천 달러, SA EPS 소수 둘째 자리 등)를 핑계로 "비슷하면 ①" 처리 금지 — ① 은 완전히 같을 때만. 표기 단위 반올림은 ② "외부 표기 단위 반올림"으로 정확한 식(round(앱, 단위) = 외부값)이 성립할 때만 분류. 실제 사례: 인포맥스 비교가 백만 단위 허용으로 돌아 매출 LTM 3건(IBM·MCD +100만, TER −124.8만)과 매출원가 LTM(NFLX·NVDA)이 ① 로 숨었다.

외부 표기 단위 반올림은 독립 근거로 인정 안 함(오너 2026-09-26 결정): round(앱, 외부 단위) = 외부값으로만 설명되는 차이는 ②도 ①도 아니고 "검증불가(외부 정밀도 부족)". 공통모드(앱과 같은 규칙·데이터로 판정한 통과)도 통과·①·②로 세지 않고 별도 상태 — 검증기 독립성은 코드 import 여부가 아니라 규칙·데이터 독립으로 판단(2026-09-26 점검에서 약 600건 공통모드 통과 발견, "검증기 독립" 주장은 틀렸음).
