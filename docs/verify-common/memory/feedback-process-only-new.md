주기적으로 도는 수집·판정 작업은 직전 이후 **새로 나온 항목만** 처리한다. 이미 받은 기사·이미 판정한 기사는 저장된 결과를 그대로 쓰고 다시 가져오거나 다시 판정하지 않는다.

**Why:** 2026-10-03 오너 "종목뉴스도 내가 말했는데 기존말고 신규로 있었는지만 대상인데 넌 다했을것같다" — 실제로 종목뉴스 미리 수집은 갱신마다 최근 1주일 기사 약 72건 전체를 다시 받아 Claude 로 다시 판정했다(9~10월 월 상한 소진). 오너가 전에 말한 지시가 코드·문서 어디에도 남아 있지 않았다 — 지시를 기록하지 않은 것 자체가 실패.

**How to apply:** 새 수집·판정 로직을 만들거나 고칠 때 "직전 결과 저장 → 새 항목만 처리"를 기본 설계로 하고, 오너 지시는 받는 즉시 CLAUDE.md·docs 에 기록한다. 관련: [[feedback-news-llm-google-only]], [[feedback-report-costs-proactively]]

**재발(2026-10-10)**: 검증기가 같은 원칙을 어겼다 — 실행마다 종목별 DART 공시 목록(list.json)을 새로 받고, DART XBRL 점검(800) 중에도 실패 요청을 매 실행 반복(하루 740건). 오너 "이건 저번에도 말했던 것 아닌가". 외부 API 조회도 같은 원칙: **이미 받은 것은 디스크에서, 다시 묻는 것은 "바뀌었을 수 있는 것"만 정해진 주기로, 실패·점검 응답도 기억해서 반복하지 않는다.** 새 조회 코드를 만들 때 "두 번째 실행의 외부 요청 수"를 재서 0 에 가까운지 확인한다.
