## 1. 렌더링 (대체 글꼴 — 그리고 못 한 것)

- 목표: `soffice → pdf → pdftoppm -r 150`. **실패.** 2호기에는 `libreoffice-core` 만 있고 `libreoffice-impress`(프레젠테이션 가져오기)가 없다 — 어떤 pptx 도 "source file could not be loaded"(10-10 참고 결과물 `005930-trust-onepager.pptx` 도 동일). 진행 기록에는 "LibreOffice 24.2 설치"라 돼 있으나 Impress 는 미설치 상태다.
- apt 캐시에 `libreoffice-impress`·`-draw` 는 있으나 의존 패키지 `libwpd-0.10-10`·`libetonyek-0.1-1` 등이 캐시에 없다 → 설치에 외부 네트워크 필요 → 지시(외부 요청 금지)에 따라 중단. 시도 중 `dpkg -i` 로 풀린 draw·impress·libwpg 는 **다시 제거**해 dpkg 상태를 깨끗하게 돌렸다(`dpkg --audit` 이상 없음). 의존 라이브러리 몇 개(libcdr·libvisio 등)는 설치된 채 남았다(무해).
- 대신 만든 것: `~/ppt/out/layout-map.png` — 개체 좌표로 그린 배치 도식(글꼴·내용 없음, 이미지는 커밋 안 함). 템플릿에 들어 있는 그림 2장(`image6.png` 로고 · `image7.png` 외부 차트 캡처)은 직접 열어 확인함.
- 한화고딕 EL/L 은 회사 글꼴이라 이 서버에 없다(렌더링해도 대체 글꼴 → 글 너비 근사). §5 의 글자 수 추정은 **한글 1em·영문/숫자 0.55em·띄어쓰기 0.3em 가정**이라 회사 PC 에서 확인이 필요하다.

A1 "일자", B1 "삼성전자", C1 "KOSPI(우)". **실제 데이터는 2~855행**(854일, 2023-01-02~2026-07-03, 날짜는 엑셀 일련번호), 856행 이하는 빈 칸. 계열 참조는 `Sheet1!$B$2:$B$2200`·`$C$2:$C$2200`·카테고리 `$A$2:$A$2200` — 2,199행 범위인데 값은 854개(나머지 빈 점). 이 숫자 범위가 "데이터 편집"으로 열리는 범위다. 표(Table)·이름 정의 없음, 열 서식: 일자(`s=8`) · 주가 `#,##0` · 지수 `#,##0.00`.

#### 요구사항 §6 이중 축 시작점 맞춤 — 구현 규칙(제안)

실제 값 그대로 그리고(100 환산 없음) **축 min/max 만** 계산한다. 입력: 주가 P, 지수 I(같은 날짜 열), 시작 값 p0=P[0], i0=I[0].

1. 구간 수 N=5 고정(눈금 6개 — 템플릿과 같게, 양쪽 눈금이 같은 높이에 오도록).
2. 각 축마다 후보 `(min, max=min+N·step)` 를 만든다: step = {1, 1.5, 2, 2.5, 3, 4, 5, 6, 7, 8} × 10^k, min 은 **단위 u = 10^⌊log10 step⌋ 의 배수**(0 이상 — step 배수일 필요 없음, 오너 답 10-15 「눈금 수치 변동 가능」), 조건 = 데이터 전 구간이 **2% 여백**을 두고 [min, max] 안(최저·최고 값이 축 밖으로 잘리지 않음 — 템플릿의 49,900 < 50,000 결함 방지).
3. 두 축 후보 쌍 중 **시작 위치 비율** f=(시작값−min)/(max−min) 의 차 |f_P−f_I| 가 허용 오차(**2%**, 오너 답 10-15) 이내인 쌍 가운데 **범위/데이터폭 비율의 합이 가장 작은 쌍**(선이 차트를 가장 넓게 씀)을 고른다. 없으면 차이가 가장 작은 쌍(오차 기록).
4. 결과 min/max/major unit 을 두 `valAx` 의 `scaling`·`majorUnit` 에 쓴다(자동 축 아님), 눈금 간격은 step. 기록: 차이·범위 비율을 로그/검증 파일에 남김.
5. 검증(결과 파일을 다시 읽어): 양쪽 축 min/max 가 규칙대로, 데이터 전 구간이 축 안, 시작 비율 차이 ≤ 허용 오차.

시험(`~/ppt/work/axis_proto.py`, 저장소에 안 올림 — 템플릿의 주가·KOSPI 값으로): 위 규칙대로면 **주가 0~400,000 · 지수 0~15,000**(시작 비율 13.9% / 14.8%, 차이 0.96%) 가 나온다 — 시작점은 맞지만 두 축이 0 에서 시작해 선이 위쪽 절반에 몰린다(범위/데이터폭 1.28 / 2.18). 템플릿은 오히려 **50,000~400,000 / 2,000~10,000**(축을 0 이 아닌 값에서 시작, 시작점 차이 1.25%)로 더 꽉 채웠다. 그래서 질문 5: ① 0 에서 시작해도 되나 ② 허용 오차를 1% 로 할지 1.5~2% 로 늘려 템플릿처럼 더 꽉 채울지 ③ 눈금 구간 수 5 고정 또는 4~7 허용. (지금 제안의 기본값은 ③ 4~7 허용·오차 1%·0 이상.) **이 규칙은 상한 알고리즘 제안이며 오너 확인 후 구현**한다.

**오너 답 반영 후 재시험(10-15, `~/ppt/work/axis_proto2.py`, 같은 템플릿 데이터 — 주가 49,900~363,500 · 지수 2,219~9,115)**: 오차만 2% 로 넓히면 결과가 그대로(0 시작)였다 — 원인은 오차가 아니라 「min = step 배수」 조건(템플릿 50,000 / 70,000 도 이 조건에선 불가). 조건을 위 2번처럼 바꾼 결과:

| 여백 · 오차 | 주가 축(간격) | 지수 축(간격) | 시작 높이 차 | 채움(데이터폭/축폭) |
|---|---|---|---|---|
| 2% · 1% | 40,000~440,000 (80,000) | 2,000~9,500 (1,500) | 0.87%p | 78% / 92% |
| **2% · 2% (채택)** | **40,000~390,000 (70,000)** | **2,000~9,500 (1,500)** | **1.42%p** | **90% / 92%** |
| 템플릿(수작업) | 50,000~400,000 (70,000) | 2,000~10,000 (1,600) | 1.25%p | 90% / 86% (최저가 1점 잘림) |

여백 0~2% 는 결과가 같았다. 0 시작은 더 이상 나오지 않는다.

### 차트2 — 도넛 (`ppt/charts/chart2.xml`, 개체 #16)
