# 종목 1페이지 — 발표자료 작성 화면 설계안 (2026-10-31, 화면은 미구현)

오너 결정 발표 1~6(2026-10-31)과 「생성 버튼 = 커넥터 작업 시작 신호」 지시를 반영한 설계안. **화면은 이 안 확인 뒤 구현**한다.
이미 만든 것: 생성 핵심(`scripts/ppt/onepager.mts` — 종목 하나 + 회사별 설정 → 슬라이드), 공용 회사 설정 저장소(`src/lib/ppt/store.ts`),
공용 검증(`src/lib/ppt/validate.ts`), API 자동 채우기(`src/lib/ppt/claude-fill.ts`·`/api/ppt/autofill`·`scripts/run/ppt-fill.mts`),
리포트 그림 후보 추출(`scripts/ppt/research-figures.mts`).

## 1. 화면 — `/ppt` (관리자·로그인 사용자, 유니버스 메뉴 옆)

| 영역 | 내용 |
|---|---|
| 위 줄 | 상품명(입력값, 기본 템플릿 문구) · 대상(유니버스 전 종목 / 고른 종목) · **생성** 버튼 · (API 켜짐일 때) 「API 로 자동 채우기」 선택 · 이번 달 API 추정 비용 / 월 상한 |
| 종목 표(한 줄 = 한 종목) | 종목명·코드 · 로고(작은 그림, 누르면 후보 3~5개에서 고르기) · **점유율 사업**(드롭다운 — 공시 부문·제품 후보 + 저장된 점유율 사업, 값·출처·기준 시점 작게) · **핵심 사업 그림**(리포트 그림 후보 중 고르기, 그림 출처 표시) · 투자포인트 세 줄 상태(채움·빈칸·오래됨) · 미리보기(작은 슬라이드 그림) · 마지막 변경(누가·언제) |
| 종목 펼침 | 점유율: 후보 값 비교(API·커넥터·사업보고서 본문 — 「사람이 고름」 표시), 출처 주소 · 투자포인트 세 줄 편집(문장별 출처 보기) · 그림 후보 목록(쪽·캡션·종류) · 변경 기록 |
| 생성 진행 | 작업 번호 · 대기/진행/완료 종목 수 · 「지금 만들기」 · 내려받기(한 파일 / 종목별 선택) |

## 2. 생성 흐름(오너 지시 2026-10-31)

1. **생성**을 누르면 비었거나 오래된 종목 목록을 그 생성 건(**작업 번호**)으로 저장한다(`ppt_jobs`, 60일 TTL).
2. 채우는 방식
   - 가) **커넥터**(기본): 작업 번호가 들어간 요청문이 채워진 claude.ai 새 대화를 연다(주간 리포트 「Claude로 작성」과 같은 구조). 오너가 보내면 구독 안에서
     `get_ppt_pending(작업 번호)` → 웹검색 → `save_ppt_share` / `save_ppt_points`(설계 `02-points-connector.md`).
   - 나) **API 자동 채우기**(키가 있을 때만 선택 가능, 관리자): 작업 번호의 종목을 `/api/ppt/autofill` 로 5종목씩 차례로. 월 상한·같은 종목 두 번 안 함.
3. 화면은 작업 번호 상태(대기·진행·완료 종목 수)를 보여 주고, 다 채워지면(또는 「지금 만들기」) 발표자료 파일을 만든다. 채워지지 않은 종목은 빈칸 + 사유로 생성.
4. **결과물 = 유니버스 전 종목을 한 파일(종목당 한 장)**(발표 5 「가」), 종목별 따로 내보내기는 선택. 한 파일 = 템플릿 슬라이드를 종목 수만큼 복제해 이어 붙임.

## 3. 저장소(발표 6 「가」 — 공용, 계정 무관)

| 컬렉션 | 키 | 내용 | 보관 |
|---|---|---|---|
| `ppt_company` | `시장:종목코드` | 점유율(사업·기준 시점·회사별 비중·출처·확인 여부)·점유율 후보(사람이 고를 것)·투자포인트 세 줄(문장별 출처)·로고·핵심 사업 그림 선택·표시 이름 | 계속(종목이 유니버스에서 빠져도 남김) |
| `ppt_company_log` | 자동 | 누가(이메일·「claude-api」·「claude-connector」)·언제·무엇을(이전·이후 값) | 2년 TTL |
| `ppt_ai_usage` | 자동 | API 호출마다 토큰·검색 수·추정 비용 | 400일 TTL |
| `ppt_jobs` | 작업 번호 | 대상 종목·종목별 상태·채우는 방식·만든 사람 | 60일 TTL |
| 그림 후보 | 종목별 | 리포트 그림 PNG(디스크 — 1호기 `/opt/macro/ppt-figures`, DB 에는 메타데이터만: 증권사·제목·발행일·쪽·캡션·종류·파일 경로) | 90일 TTL(리포트 보관과 같게) |
| 로고 | 종목별 | 고른 로고 PNG(디스크), 메타데이터(출처·고른 사람) | 계속 |

용량: 그림 후보 실측 1개 평균 약 121KB(5종목·리포트 15개·후보 158개 = 19MB). 유니버스 120종목 × 최근 리포트 3개면 약 3,800개·460MB 로 Atlas 무료(512MB)에 넣을 수 없어 **그림 파일은 1호기 디스크**, DB 는 메타데이터만(종목당 수 KB).

## 4. 화면에서 하지 않는 것

- 화면이 Anthropic API 를 직접 부르지 않는다(서버 라우트만, 관리자만).
- 투자포인트 출처는 슬라이드에 적지 않는다(발표 4) — 화면 펼침에서만 보인다.
