# 종목 1페이지 — 투자포인트 커넥터 설계안 (2026-10-31, 구현 전)

오너 지시(2026-10-31): 투자포인트 칸 내용은 **claude.ai 사용자 정의 커넥터(MCP)** 로 Claude 검색을 붙인다. 주간 리포트 커넥터와 같은 구조
(`src/lib/server/mcp-weekly.ts`, `/api/mcp/<WEEKLY_MCP_TOKEN>`, 상태 없는 JSON-RPC, 오너 구독 안에서 돌아 비용 0, **앱에 Anthropic API 호출 코드 없음**).
**실제 도구 구현은 오너가 내용 규칙을 확정한 뒤**. 이 문서는 자료 구조·도구·작성 규칙 설계안이다.

## 1. 자료 구조 (생성 핵심에 이미 반영 — `scripts/ppt/onepager.mts` `OnepagerSettings.points`)

```ts
points: {
  kind: "founding" | "business" | "thesis";   // ① 설립연도·사업·점유율 ② 현재 사업 부문과 차별점 ③ 종합 핵심 투자포인트
  text: string;                                 // 한 줄(칸 폭 약 26.6cm·14pt — 넘치면 글을 줄인다, 글자 크기는 그대로)
  sources: { title: string; publisher: string; publishedAt: string /* YYYY-MM-DD */; url?: string }[];
}[]
```

- 저장 자리: **종목별 회사 설정** — 발표자료 작성 화면(미정)이 저장할 점유율 사업 선택·핵심 사업·로고와 같은 저장소 한 문서에 둔다
  (저장소 범위 — 계정별/공용 — 는 오너 결정 대기, 아래 §5).
- 생성기는 출처(매체·발행일)가 없는 문장을 넣지 않고 빈칸 + 사유로 남긴다. 슬라이드에는 출처를 문장마다 적지 않고 **하단 출처 한 줄**에
  매체를 중복 없이 모은다(오너 2026-10-31). 문장별 출처는 설정 문서에만 보관(검증·편집용).

## 2. 도구 (안)

| 도구 | 입력 | 돌려주는 것 / 하는 일 |
|---|---|---|
| `get_ppt_points_data` | market, symbol | ① 회사 기본: 이름·설립연도 원자료(한국 DART 기업개황 est_dt / 일본 유가증권보고서 沿革 설립 / 미국 — 시험 결과로 결정) ② 사업 부문(공시 기준 목록·부문 매출이 있으면 금액과 출처) ③ 점유율 칸 설정 값(사업·수치·출처·기준 시점 — **같은 값을 첫 줄에 재사용**, 새로 만들지 않음) ④ 재무 요약(앱 하이라이트 값 그대로) ⑤ 최근 공시 제목·리서치 제목(앱 DB `kr_research` 등, 발행일·주소) ⑥ 작성 규칙 guide(§3) ⑦ 칸 용량(줄당 글자 수 근사) |
| `save_ppt_points` | market, symbol, points(§1), preview?: boolean | 검증(§4) → 통과한 문장만 종목 설정에 저장. preview 면 저장하지 않고 검증 결과·지워질 문장·줄 폭 추정만 돌려줌. 발행·삭제 도구는 없다 |

## 3. 작성 규칙 (guide 에 넣을 내용 — 오너 2026-10-31 확정분)

세 줄, 한 줄씩:
1. **첫 줄 = 설립연도 + 회사의 사업 + 점유율 등(회사 소개 한 줄).** 설립연도는 공식 원자료(위 ①). 점유율은 점유율 칸과 같은 출처·기준 시점 값만.
2. **둘째 줄 = 현재 진행 중인 사업 부문과 그 차별점.** 사업 부문은 공시 기준(사업보고서 「사업의 내용」·부문 주석·유가증권보고서 事業の内容).
   차별점은 출처가 있는 문장만(회사 공시·실적 발표·증권사 리포트·주요 매체 기사, 발행일 필수). 출처 없는 비교·우위 주장은 남기지 않는다.
3. **셋째 줄 = 종합 핵심 투자포인트.** 근거 문장 출처 필수(증권사 리포트·공시·실적 발표·주요 매체, 발행일 필수). 근거 없는 전망·목표가 문구 금지.

공통: 수치는 출처 필수(get 이 준 값 또는 출처 본문에 있는 값). 블로그·카페·커뮤니티·SNS·유튜브 출처 무효. 줄마다 칸 폭 안 — 넘치면 글을 줄인다.

## 4. 검증 (주간 리포트 검증 재사용 방향)

- 출처마다 발행일 필수, 블로그·SNS 등 무효 판정은 `src/lib/weekly/generate.ts` 의 무효 주소 규칙을 공용 모듈로 빼서 같이 쓴다.
- 문장 단위 삭제: 무효 출처만 단 문장, get 자료에도 유효 출처에도 없는 수치(%·배·원·달러·엔·건 등)가 든 문장은 지운다(주간 리포트와 같은 「같은 단위로 있는지」 대조 — 한계도 같음).
- 첫 줄의 설립연도·점유율은 get 이 준 값과 정확히 같아야 한다(다르면 그 줄 삭제).
- 셋째 줄의 목표주가·「상승 여력」류 문구는 지운다.
- 줄 폭 추정(한글 1em·영문/숫자 0.55em, 14pt, 26.6cm)을 넘으면 저장은 하되 경고 — 생성기도 같은 판정으로 보고서에 남긴다.

## 5. 기존 커넥터 주소에 더할지, 새 주소로 뺄지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| 가. 기존 주소에 도구 추가 | `/api/mcp/<WEEKLY_MCP_TOKEN>` 의 tools 에 두 도구를 더한다 | claude.ai 커넥터 설정 하나로 끝, 토큰·인증·전송 코드 그대로 | 주간 리포트 대화에서도 PPT 도구가 보여 모델이 잘못 고를 수 있음, 서버 이름·안내문이 주간 리포트 중심, 한쪽 고장·토큰 교체가 둘 다에 영향 |
| 나. 새 주소 | `/api/mcp-ppt/<PPT_MCP_TOKEN>` 별도 서버(같은 JSON-RPC 처리 코드를 공용 모듈로 나눠 씀) | 도구 목록·안내문이 PPT 전용이라 모델 혼동 없음, 토큰·권한을 따로 끊을 수 있음 | claude.ai 에 커넥터를 하나 더 등록, 1호기 app.env 에 토큰 하나 더 |

추천: **나** — 도구 목록이 섞이지 않는 쪽이 모델 실수가 적고, 공용 처리 코드를 나누면 추가 코드는 도구 두 개뿐이다.
